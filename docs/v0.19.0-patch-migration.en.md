# v0.19.0-patch migration and acceptance

[中文](v0.19.0-patch-migration.md) · [Tracking issue #20](https://github.com/codeasier/dsh-TUI/issues/20)

## Scope and baselines

- New baseline: upstream v0.19.0, `224f847d02c2157f43862d2792cf9d7459222f4c`.
- Custom source: the 12 commits from v0.16.1 `73ff99fbed56563bf154d719effd09f9f9725349` to v0.16.1-patch `c619ba52260694aac6b8415f30e62608092f2f73`.
- The upstream primary DSH validation line is **0.2.2-rc.1**, with its compatibility list unchanged. This does not claim support for an unverified 0.2.2 stable release.
- Capabilities are ported separately rather than cherry-picking the entire sequence. Old deployment records and package IDs remain historical evidence on the old branch, not proof of a new installation.

The port covers installation safeguards and ag-search, jobs/provider/catalog and `/fast`, read-only OpenCode import, stderr/sharp, themes/transcripts, hanging indentation/inline history/IME, Unicode editing and in-place multiline Launchpad, and source-copy actions for code blocks/tables.

Preserve v0.19.0 onboarding sign-in/model selection, official worktrees, plugin grant revocation on disable/unload, ended sessions and held input after host unload, soft-wrap/pane copying, and expanded tool-card backgrounds. In-place Launchpad newlines intentionally replace the upstream newline-to-Chat interaction; batched-input, image-token atomicity and suspended-composer readiness protections must remain.

## Relationship to the v0.18.0 port

[PR #19](https://github.com/codeasier/dsh-TUI/pull/19) at `7c99f26c51f5a3bf58bb3eb64142713744615399` supplies implementation only. This branch starts directly from v0.19.0, has no merge dependency on PR #19, and inherits none of its unrun CI conclusions. Its single aggregate commit was replayed, then conflicts and automatically merged semantics were reviewed separately.

- Preserve upstream `/update` alignment of the host engine, global launcher and profile, both boot-entry checks, and failure isolation/recovery. Add only the customized stdin handoff protection.
- Keep the upstream 0.2.2-rc.1 host contract, lockfile, patch/host replica snapshots and pinned-source CI lane. Do not restore the rc.5 baseline.
- Preserve durable model selection, session host unload, held-input snapshots, tool scope, channel failure warnings and input composition/focus behavior.
- Smooth reveal remains root- and session-scoped; completed rows do not replay on remount. Customized tool cards show bounded previews immediately and reveal expanded output in full.

- Official listing discovery only applies to catalog routes without custom endpoint, protocol or connection-header overrides, including inherited configuration. An initial override is skipped before credentials are read. Changes while awaiting credentials or the catalog are rechecked before the request: credentials are not forwarded to the fixed official endpoint, and derived routes are not rewritten.

## Known storage boundary

OpenCode uses read-only SQLite transactions for consistent main-DB/WAL session data, but SQLite may create or update the source `-shm` sidecar, including browsing, counts and dry-runs. Strict source-directory zero-write behavior is neither implemented nor verified. An unproven copy of an active database does not replace the consistent reader. See the [migration boundary](migrate.en.md#opencode-support-boundary).

## Automated acceptance

Routine UT/build runs belong in repository CI, not a local substitute. Fork Actions are currently disabled and activation has not been authorized, so the following is an acceptance plan, not a pass record.

Use Node 24 and the pnpm version declared in package.json. Initialize submodules, then let the existing CI compile once and reuse that exact output across groups. A clean textual merge or syntax check is not a successful build.

```sh
git submodule update --init --recursive
pnpm install --frozen-lockfile --ignore-scripts
pnpm compile
pnpm verify:build
pnpm verify:package
pnpm smoke
node scripts/run-ci-group.mjs render-scroll
node scripts/run-ci-group.mjs input-terminal
node scripts/run-ci-group.mjs session-workspace
node scripts/run-ci-group.mjs channel-ui
```

Check `ci-gate` and every required group for the final commit, including `alpha-compat` against the pinned 0.2.2-rc.1 source. Record upstream observation jobs with their existing non-blocking status; skipped or unrun is not passed. Added regressions cover installation ownership/rollback/corepack absence, stubbed ag-search, provider/OAuth, synthetic OpenCode SQLite/WAL, job caches, IME, hanging wraps, Launchpad and block copying. ag-search must be in the npm tarball, and local installation must compare both `lib` and `presets`.

## Real-terminal checklist

This is a procedure to run, not a claim of completed device verification. Use an authorized test profile and synthetic conversations. Do not overwrite production profiles, read private history or make paid model calls for automated regression checks.

1. **Environment:** record the candidate commit, Node/DSH/TUI versions, OS, terminal, and SSH/tmux use. Verify the loaded package matches the candidate. Cover inline/fullscreen, narrow widths and a wide split layout.
2. **Editing:** exercise unspaced Chinese, punctuation, emoji and combining characters in Launchpad and Chat. Check word motion/deletion, replacement selections and atomic image-chip deletion. Launchpad grows in place on newline and follows the cursor beyond six lines. Batched input, paste and submission must not lose text or duplicate images; drafts survive model settings and onboarding transitions.
3. **IME and terminal handoff:** compose Chinese at the right edge without stale dark bands after commit; ordinary motion must not erase preedit. Exercise `/restart`, normal exit and failure cleanup. Restore raw mode, cursor, background, mouse and synchronized output, without inserting terminal replies into the draft.
4. **Transcript and copy:** partially select long code, nested lists, tables, wide characters and hard/soft wraps. Exclude display indentation and borders. Code/table buttons preserve source indentation, blank lines and trailing whitespace. Streaming copies current content; narrow/inline modes hide unavailable actions. Pane copying stays within its pane, with no stale selection after resize.
5. **History and jobs:** scroll long history, resize, toggle `Ctrl+O`, expand/collapse tools, resize panels and change concurrent job titles. No transcript loss or stale row-height reuse. Only persisted hand-off evidence promotes work to a background job.
6. **Lifecycle:** enable, disable and unload a test plugin and verify grant revocation. Unloading the host listener must end its session; undelivered input stays held without automatic replay, and remount requires explicit recovery.
7. **Providers and import:** cover zero/one/many model onboarding paths and confirm catalog discoveries never auto-enable models. Stub `/fast` to verify next-request application, no persistence across restart and unaffected unsupported protocols. Test OpenCode read-only DB/WAL, compaction/revert and idempotency using synthetic data only.
8. **Updates:** use an isolated profile to check three-layer `/update` alignment, preserved host-skip reasons, both boot entries and failure recovery. Held inputs must not cross sessions or be delivered twice after update/restart.
9. **Installation:** in isolated temporary HOME/profiles, exercise missing corepack, ownership conflicts, profile locking, failed-install rollback and independent `lib`/`presets` mismatches. A real install needs separate authorization; generate and verify a new package ID rather than reusing old device records.

An acceptance record must name the commit, scenario, passed/failed/not-run result, evidence and remaining issues. This migration does not tag, release or deploy, and must not be called deployed before actual device acceptance.
