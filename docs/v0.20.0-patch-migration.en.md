### Intentional customization differences

- Launchpad newlines still grow the composer in place instead of entering Chat. Retain batched-input, atomic image-chip deletion, focus/composition and suspended-composer readiness safeguards.
- Tool cards retain bounded previews and paint complete details on click or `Ctrl+O`, without line-by-line animation. `smoothStreaming` still applies to replies and expanded thinking; replay/history paint directly. Expanded cards honor the selected background, including an explicitly unfilled `none`.
- Preserve the neutral-gray canvas, bold yellow user-prompt/composer rail, quiet ordinary-tool summaries and hanging indentation. Original-source copy buttons coexist with upstream soft-wrap and pane selection.
- Retain installation/update safety and `/update` stdin handoff protection without replacing v0.20.0 adapters, lockfiles or host snapshots with older versions.

## Conflict-integration details

- A durable partial `compactPreview` takes precedence over exact legacy-wrapper decoding. Expanded new partial checkpoints retain their full raw text; preview clipping and legacy decoding are not applied to the expanded body.
- Edit/Write cards combine upstream git-hunk diffs, the customized maximum eight-row folded diff preview, and left-rail geometry. Retaining the old preview must not restore whole-file diffs or consume the body's available width.
- Retain both `inline-shrink-to-fit` and `reanchor-growth` gates, updating fixture output sequences and geometry expectations for the composition. These regressions were not run in this migration; updated assertions are not acceptance evidence.

## Known storage boundary

OpenCode's read-only SQLite transactions keep main-DB/WAL session data unchanged by the importer and provide a consistent snapshot. SQLite may still create or update the coordination sidecar `-shm` in the source directory, including during browsing, counts and dry-runs. **Strict source-directory zero-write behavior is neither implemented nor verified.** Do not substitute an unproven temporary copy of an active database. See the [OpenCode support boundary](migrate.en.md#opencode-support-boundary).

## Verification status and pending CI

Static review covers source commits, version/host contracts, retained upstream behavior and conflict resolution, bilingual descriptions and packaged guide mirrors. Static review, absence of conflict markers and byte equality do not establish a successful build, regression run or terminal acceptance.

**Not run:** routine UT/build, full build gates/regressions, real-terminal acceptance, Windows toast/jumpBack, actual installation/update and device acceptance. Routine UT/build is not run in the cloud as a substitute; fork Actions remain paused and this migration does not enable or rerun them. The commands below are only a plan for a later authorized run; unrun or skipped does not mean passed.

Repository CI should use Node 24 (at least 24.9 for the host) and the pnpm version in `package.json`, compiling once and sharing that exact output:

```sh
git submodule update --init --recursive
pnpm install --frozen-lockfile --ignore-scripts
pnpm compile
pnpm verify:build
pnpm verify:package
pnpm smoke
node scripts/run-ci-group.mjs render-scroll
node scripts/run-ci-group.mjs input-terminal
node scripts/run-ci-group.mjs session-workspace
node scripts/run-ci-group.mjs channel-ui
```

Check the final commit's `ci-gate`, pinned rc.2 `alpha-compat` and applicable platform gates. Upstream or older-patch passes are not this candidate's passes. Preserve the non-blocking status of observation jobs. Pay particular attention to empty/text/count-only transitions and cleanup in `verify-smooth-reveal.tsx`, catalog custom-connection safeguards, install rollback/integrity and ag-search packaging, plus the v0.20.0 focused regressions above.

## Concise manual acceptance plan (not run)

Run only on a separately authorized, isolated test profile already containing the candidate package. Use synthetic conversations/SQLite databases, not private history, production profiles or paid model requests for automated regressions. Installation and `/update` mutate the environment and are outside this execution scope.

```sh
# In the authorized acceptance machine's candidate checkout, record identity.
# Do not reuse an old package ID.
git rev-parse HEAD
node --version
dsh --version
TEST_PROFILE=dsh-tui-v020-acceptance
# Prerequisite: verify this isolated profile has the candidate and DSH 0.2.2-rc.2.
dsh --profile "$TEST_PROFILE"
```

1. **Input/rendering:** in inline/fullscreen, narrow/split layouts, edit Chinese, punctuation, emoji/combining characters; enter more than six lines and move the cursor, paste/submit, and delete image chips. Resize, toggle side panels and `Ctrl+O`. Check draft loss/duplication, stale IME bands, bottom-anchored footer/short frames and blank bands after tall-frame shrink.
2. **Thinking/tools/copy:** use synthetic streams to transition empty → text → count-only → settled → streaming, expand/collapse and unmount; check hook errors and spinner cleanup. Preserve bounded tool previews/instant expansion. Select soft/hard wraps, lists, code and tables; source-copy buttons retain blank lines/indentation/trailing whitespace and pane selections stay isolated. Check unified diffs with/without true offsets, multiple hunks and large-change fallback.
3. **Sessions/host:** with synthetic records check live/replayed/tree partial checkpoints, durable job descriptions and background hand-off, durable model/effort, grant revocation and held input after host unload. Exercise rc.2 `/team on`, `/team off` and detached-session attribution. Test older-host fallback separately, without sharing a store written by rc.2.
4. **Providers/import:** stub official discovery with zero/one/many models, connection overrides and in-flight changes; discoveries must not auto-enable models. `/fast` affects the next request without changing effort and resets to the configured default after restart. Use synthetic OpenCode DB/WAL for compaction/revert, idempotency and sidecar boundaries; do not claim zero source-directory writes.
5. **Notifications/handoff:** use test events for all four notices, unfocused/off, session changes, dismissal/late responses, actual account-card paint and language refresh. Separately test Windows `jumpBack` success and safe fallback for unverifiable/disappeared targets. Check raw mode, cursor, background, mouse and synchronized output after normal exit, `/restart` and failure cleanup.
6. **Install/update (separate authorization):** in isolated HOME/profiles, follow `scripts/local-install.sh` for missing corepack, ownership conflicts, profile locks, rollback and independent `lib`/`presets` mismatches. That script compiles and is not run in this migration. Separately check `/update` three-layer alignment, both entries, host-skip reasons and recovery. Record a new package ID and read back the loaded path; held input must not cross sessions or replay twice.

For every acceptance item, record the candidate commit, actual package/host versions, environment, passed/failed/not-run result, evidence and remaining issues. Until those checks are complete, this document does not establish merge readiness, release readiness or deployment.
