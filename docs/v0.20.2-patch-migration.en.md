## What still needs to run

Source and registration checks are not a build, a real rendered screen or a package test. No dependencies, full CI, package, profile install/upgrade, real terminal or Windows/macOS acceptance were run here. Upstream CI, an older package or a skipped test does not prove anything about this candidate. Keep fork Actions paused.

When a runner for the exact candidate is authorized, initialize submodules, use a frozen install and reuse the same compilation:

```sh
git submodule update --init --recursive
pnpm install --frozen-lockfile --ignore-scripts
pnpm compile
pnpm verify:build
pnpm verify:package
pnpm smoke
for group in render-scroll input-terminal session-workspace channel-ui; do
  node scripts/run-ci-group.mjs "$group" || exit 1
done
pnpm verify:local-install-ownership
pnpm verify:local-install-rollback
```

Record the exact head, host, OS/terminal, commands and outcomes. Capture real inline/fullscreen output and the narrow-width case. Before accepting an installed build, hash the actual candidate tarball and verify its lib, presets and guide contents in an isolated profile; do not install a same-version registry package in its place. Keep the old host's session store separate. OpenCode reads can update SQLite `-shm`; use a disposable fixture. Do not use a production profile or publish to validate this migration.
